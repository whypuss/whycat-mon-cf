## CHART-001 · 折线全黑（已修复）

**现象**：多条历史折线呈黑色，与 tooltip 色点、底部摘要色点的颜色不一致。

**根因**：ECharts 走 `CanvasRenderer`，序列颜色最终落到 canvas 2D 的 `strokeStyle`，
而 **canvas 不解析 CSS 变量**——赋一个 `var(--emerald)` 会被直接丢弃，
线条留在上一次的绘制样式上。本主题此前在
`domain/server-detail.ts` 的 `COLORS` 里写的就是 `var(--emerald)` / `var(--blue)` /
`var(--amber)` / `var(--violet)` / `var(--red)`，同一批值又用于
HTML tooltip 的色点与底部摘要色点——HTML 一侧能解析、canvas 一侧不能，
于是出现「折线全黑但色点正常」这种前后不一致。

**像素证据**（1440×900 / 浅色 / 本地生产构建，`getImageData` 直接读画布）：

| 区域 | 修复前 | 修复后 |
|---|---|---|
| 绘图区（9 张图逐张取样） | 只有 `0,0,0` | `#FF6B6B` / `#4ECDC4` / `#A78BFA` / `#60A5FA` / `#FFB347` |
| 底部 HTML 摘要色点 | `rgb(15,159,120)` 等（正常） | 与绘图区**逐一相等** |

**修复**：新增 `src/utils/chart-palette.ts`，逐字移植上游 `utils/chartPalette.ts` 的
`DEFAULT_SERIES_PALETTE` / `ACCESSIBLE_SERIES_PALETTE` / `ACCESSIBLE_LINE_TYPES`，
另按上游 `LoadChart` / `PingChart` 的 `chartThemeColors` 移植一份 `getChartThemeColors(dark)`。
调色板由 `ServerDetailView` 按色觉设置派生后传进两个构建器（对应上游 `LoadChart`
把 `chartColors` 传给图表卡的做法），**在统一的配置层处理，没有逐图打补丁**。

同一批取样在上游 Komari 详情页得到同一组色值（`255,107,107` / `96,165,250` /
`167,139,250` / `78,205,196`），确认配色来源一致。

## CHART-002 · 浅色模式图内文字偏白（已修复）

上游同位取样同样是 `0,0,0@α≤140`，两版一致。

## CHART-003 · 悬浮网络图曲线消失（未复现，记录复现条件）

**结论：在本轮候选构建中未复现。**

复现尝试覆盖：1440×900 与 375×812、浅色、`实时网络`（两条序列）、
在绘图区 25% / 50% / 75% 三个横向位置悬浮、悬浮后移出。
每一步都直接读画布统计两条序列的像素数：

| 状态 | 序列像素数 |
|---|---|
| 未悬浮 | `#4ECDC4`×649、`#60A5FA`×528 |
| 悬浮 25% / 50% / 75% | 完全相同 |
| 移出 | 完全相同 |

即曲线没有被隐藏、没有被 blur 状态调暗、也没有被重绘成背景色。

可观察到的**相关事实**：tooltip 配置是 `confine: true`（上游 `LoadChart` 的
`baseTooltipConfig` 是 `confine: false`），气泡被限制在图表框内，
1440 下覆盖绘图区约 11%、375 下约 21%，会遮住一部分曲线。
这解释「看起来像消失」的观感，但不构成曲线本身消失。

同时要记录的是：**修复前**所有折线都是黑色，且颜色赋值无效意味着重绘时
canvas 会沿用上一次的绘制样式——这类「取决于绘制顺序」的表现本身就不稳定。
CHART-001 / 002 修复后颜色是固定字符串，重绘路径不再有不确定性。

> **待用户确认**：若在正式版实际应用后仍能观察到该现象，请提供触发时的
> 视口、主题、具体图表与序列数量，本轮的像素采样脚本可以直接复用。

## v1.1.8 · 短时高值段与安静邻域（已发布）

**起因**：线上真实数据里出现两种 v1.1.7 漏判的形态，纵轴照旧被撑到很高。两者与时间窗口无关，1 / 6 / 12 / 24 小时都能出现。

| 形态 | 线上样本 | v1.1.7 | v1.1.8 |
|---|---|---|---|
| 相邻两个高点 | 节点 C · 移动，12 小时窗口，常态约 80ms，23:02 与 23:06 分别为 584ms 与 604ms | 整段保留，遮蔽后最大仍是 604ms | 整段隐藏，遮蔽后最大 101ms |
| 近旁有尖峰的孤立高点 | 节点 D · 电信，6 小时窗口，17:27 的 701ms 左侧紧跟着 1219 / 1217 两个高点 | 左侧中位数被抬到 718ms，判为阶跃而保留 | 取参考邻域时跳过疑似高点，左侧回到约 200ms，正常隐藏 |

**规则变化**：
- 检测从「单个孤立高点」扩展到「短时高值段」：连续不超过 2 个采样、且真实跨度不超过 10 分钟；连续三个及以上，或跨度超过 10 分钟，仍按持续高延迟保留。
- 取参考邻域时跳过其它疑似高点，每侧最多跳过 3 个；跳过的点不进入基线，也不参与两侧中位数比较。超过上限就当作证据不足，保留。
- 其余规则不变：缺口两侧不借证据、首尾保留、阶跃与爬升保留、整条线不会被遮蔽完。

**离线回放**（线上 `/api/history/all` 只读取样，5 台节点 × 1 / 6 / 12 / 24 小时）：

| 项 | 结果 |
|---|---|
| 高点命中 | 改动前有 2 处保留的高点段，改动后全部命中；各线路遮蔽后的最大值回到常态区间（例：节点 C · 移动 604 → 101，节点 D · 电信 1206 → 229） |
| 平台与故障 | 连续三点及以上的平台、阶跃、爬升在回放中一处都没有被隐藏 |
| 固定样本 | 本地 `history=spike` 下仍是「隐藏尖峰 · 2」：移动的三点平台与原始缺口保留，任务卡统计仍为 246ms / 600ms / 198ms |

## v1.1.11 · 窗口次边缘尖峰（已发布）

**起因**：孤立高值位于时间窗口倒数第二格、右侧只积累到一个恢复正常的点时，旧规则只允许“正好位于最外侧”的高点缺少一侧证据，因此按钮仍会显示「隐藏尖峰 · 0」，纵轴继续被高值拉伸。

**规则变化**：

- 所选窗口的第二个或倒数第二个点允许使用边缘侧现有的一个样本，但另一侧仍须达到正常的最少证据数；
- 边缘侧已有样本时，必须与另一侧基线一致，真实阶跃仍然保留；
- 单点或相邻两点组成的短时高值段会整段隐藏，不会只去掉其中一个；连续三点以上仍按持续高延迟保留；
- `null`、离线占位或异常时间间隔造成的证据不足仍然不跨越，原始值、任务卡统计与 Tooltip 均不改变。

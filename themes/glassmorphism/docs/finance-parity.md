> **当前状态**：本功能已随 v1.1.7 发布。第 0 节与第 9 节前半保留的是发布前审计快照，其中“候选尚未应用”“线上部署尚未验证”等文字只表示当时状态；最终线上复验见第 10 节与 `docs/todo.md` TODO-08。

## 1. CFSM 的真实数据契约

### 1.1 接口返回字段（匿名化合成样本）

`/api/servers` 与 `/api/server?id=` 返回同一组财务字段，全部是字符串。以下行仅演示字段格式与后续计算，不是线上节点账单：

| 节点 | `price` | `currency` | `billing_cycle` | `expire_date` | `auto_renewal` |
|---|---|---|---|---|---|
| 节点 A | `"24.00"` | `"$"` | `"year"` | `"2027-03-17"` | `"1"` |
| 节点 B | `"30.00"` | `"€"` | `"five_years"` | `"2030-09-17"` | `"1"` |
| 节点 C | `"45.00"` | `"$"` | `"three_years"` | `"2028-03-17"` | `"1"` |
| 节点 D | `"18.00"` | `"€"` | `"year"` | `""` | `"1"` |
| 节点 E | `"6.00"` | `"$"` | `"month"` | `"2026-09-27"` | `"1"` |

站点开关只在 `/api/servers` 顶层的 `sysConfig`（`show_price` / `show_expire` / `show_tf`）；`/api/server` 的 `sysConfig` 只有 `long_history_points`。

**`show_price` 关闭时服务端不删价格字段**（`handlers/dashboard.js` 的 `withoutPrivateServerFields` 只删 bandwidth / note / auto_update / traffic_snapshots），隐藏完全由前端负责。

### 1.2 写入时的规范化（后端源码）

`handlers/admin.js` 的 `normalizeServerBillingData`（新增与编辑都经过它），以及旧数据迁移 `database/updateDatabase.js`：

| 字段 | 存储值 | 依据 |
|---|---|---|
| `price` | `normalizePrice`：空 → `""`；取文本里第一个数字；`-1` → `"-1"`；其它负数与非数字 → `""`；其余 → 两位小数 | `serverBilling.js` |
| `billing_cycle` | `normalizeBillingCycle`：8 个枚举之一；空或无法识别 → `"month"` | 同上；列默认值 `'month'` |
| `currency` | `normalizeCurrency`：后台 36 个选项里的符号；输入为空时存 `"¥"`；输入无法识别时存 `""` | 同上；列默认值 `'¥'` |
| `expire_date` | 表单日期 `YYYY-MM-DD` 或 `""`；`auto_renewal = 1` 时保存即顺延，每日定时任务也会在到期前一天顺延并写回 | `renewExpireDateIfNeeded`、`services/notification.js` |

因此正常数据里：价格是 `""` / `"-1"` / `"0.00"` / 两位小数；周期是 8 个枚举之一；币种是后台选项符号，`""` 只可能来自无法识别的输入。

### 1.3 CFSM 前端的语义（`finance.js` / `server.js`）

- **免费**：`isFreePrice` = 规范化后为 `"-1"` 或 `"0.00"`；汇总另外排除带 `白嫖中` 标签的节点。
- **周期天数**：月 30、季 90、半年 180、年 365、两年 730、三年 1095、四年 1460、五年 1825；未知周期按月处理。
- **月均**：`价格 ÷ 周期天数 × 30`。
- **剩余价值**：`min(价格, 价格 × 剩余毫秒 ÷ 周期毫秒)`；到期超过 100 年视为全价；已过期为 0；没有到期日时不计入剩余价值，另计「未设到期」数量。
- **币种**：`CURRENCY_ALIASES` 把后台符号与 ISO 代码映射到 43 种币种；无法识别时回退 CNY。
- **汇率**：
  - 先请求 `api.frankfurter.dev/v1/latest?base=CNY`，再请求 `open.er-api.com/v6/latest/CNY`，超时 5 秒；
  - 按本地日期缓存到 `cfsm_finance_exchange_rates_cny_v1`；
  - 返回表里缺的币种用内置表补齐，整份仍标为 `network`；
  - 显示币种为 6 种：CNY / USD / HKD / EUR / GBP / JPY。
- **展示**：只有 `show_price` 开启时才显示剩余价值卡；汇率在页面加载时就会请求，与该开关无关。

后台 36 个币种选项里，`kr` 的说明是「克朗（SEK/NOK/DKK）」，本身有歧义；CFSM 前端把它按 SEK 计算。

## 5. 汇率的适配规则

- **换算公式**：`目标金额 = 原金额 ÷ 源币种汇率 × 目标币种汇率`，CNY 固定为 1。源、目标币种相同时不需要汇率；任一汇率不是有限正数时不换算，也不显示金额。
- **精度**：内部保持完整精度，只在展示时舍入；合计直接对数值求和，不解析格式化后的字符串。
- **请求**：
  - 默认源为 `open.er-api.com`，备用源为 `api.frankfurter.dev/v1/latest?base=CNY`。上游的 frankfurter.app 地址已失效（301 跳转且不带跨域头），因此改用 CFSM 同款地址，线上 CSP 允许。
  - 单源超时 5 秒；失败后本页会话内不再重试，下次打开页面再试。
  - 同一页面共享一个进行中的请求。
  - 只有在价格可见、并且确实需要换算时才请求。
  - 请求不带凭据，也不发送任何节点信息。
- **缓存**：本主题自己的命名空间，带版本号；只保存数据源实际返回的汇率，并记录取得时间、数据源自带的日期和提供方。数据源缺的币种在使用时才由参考表补上，并标为「内置参考汇率」，不会写进缓存冒充网络值。当日缓存直接复用；跨日后先请求，失败时退回旧缓存并标为「历史缓存汇率」。
- **参考表**：来自 CFSM 2.8.5 Stable（`1dc0dc4`）`src/frontend/utils/finance.js` 的 `FINANCE_CURRENCY_CONFIG`，只在没有网络也没有缓存，或备用源缺某个币种时使用，并标为「内置参考汇率」。
- **手动覆盖**：只接受有限正数，CNY 不可改；在汇率页和使用位置都标为「手动」。「恢复今日汇率」只清除手动覆盖；当前表不是当日取得的时，按钮显示为「清除手动汇率」，不承诺网络刷新。
- **存储异常**：localStorage 不可用、配额已满或缓存损坏时，按无缓存处理，页面照常工作。

## 6. 结论与有意差异

审计没有发现需要修改 Worker / Agent / D1、增加后端代理或密钥的地方，全部在前端完成。本次按第 3、5 节实现。与 Komari `bf83765` 的有意差异如下，原因都是 CFSM 数据优先，或者不把「不知道」算成一个数：

| 项 | Komari `bf83765` | 本主题 | 原因 |
|---|---|---|---|
| 未知或空币种 | 按 CNY 计算 | 不换算，逐条注明「未标明币种」「币种无法识别」 | CFSM 用空串表示输入无法识别，当 CNY 会算错 |
| `kr` | 上游没有这个符号；CFSM 前端按 SEK | 标为「币种有歧义」，不换算 | 后台选项的说明本身就包含三种克朗 |
| 缺到期日 | 剩余价值按 0 计入合计 | 不计入，注明「未设置到期时间」 | 缺失不等于已过期 |
| 剩余价值算法 | 剩余天数向上取整，不封顶 | 毫秒比例，封顶为原价（CFSM 口径，第 4 节） | CFSM 数据优先 |
| 免费节点 | 价格 -1 或 `白嫖中` 标签 | 价格 -1 / 0，或 `白嫖中` 标签 | CFSM 的 `isFreePrice` 包含 `0.00` |
| 价格无法识别 | 上游价格是数字，没有这种情况 | 不算免费、不按 0 计入，注明「价格无法识别」；未填价格只在明细行显示「未设置」 | 不把坏数据算成 0 |
| 备用汇率地址 | `api.frankfurter.app`（301 跳转且不带跨域头，浏览器里取不到） | `api.frankfurter.dev` | CFSM 同款地址，线上 CSP 允许 |
| 汇率来源 | 整张表一个状态；缺任一币种整张作废 | 逐币种记录来源；数据源缺的币种用参考表补上并标明 | 参考值不冒充网络值 |
| 手动汇率 | 首页与弹窗生效，详情页不读 | 首页、详情页、弹窗一致，改动后实时生效 | 同一份偏好，所有使用位置结果一致 |

## 8. 请求与缓存的影响

**CFSM 后端**：不新增请求。首页与详情页的 `/api` 请求清单不变；本地实测详情页冷启动仍是 `config` / `server` / `history/all` / `servers` 四个。

**第三方汇率服务**：由访客浏览器直接请求，Worker 不参与。

| 情形 | 请求数 |
|---|---|
| 不需要换算：所有计费节点的币种都等于显示币种、价格不可见、没选财务卡，或节点列表加载失败 | 0 |
| 当日已有缓存 | 0 |
| 没有当日缓存，`open.er-api.com` 成功 | 1 |
| 主源失败，`api.frankfurter.dev` 成功 | 2 |
| 两个源都失败 | 2；本页之后不再重试，有旧缓存就用旧缓存，否则用参考表 |

- 触发位置：首页选中的财务卡可见且需要换算；明细弹窗打开且需要换算；详情页价格可见、选了剩余价值卡且节点币种不等于显示币种。
- 同一页面同时触发时共享一个进行中的请求；首页、详情页、弹窗共用一份缓存。
- 单源超时 5 秒；没有轮询，也没有定时刷新。
- 请求地址固定，不含节点名、IP、价格或节点列表；`credentials: 'omit'`，`referrerPolicy: 'no-referrer'`。汇率服务仍能看到访客的 IP 与浏览器标识，这是浏览器直连的固有情况。
- 线上 CSP 的 `connect-src` 已允许这两个地址（第 2 节）。

**对当时部署配置的影响**（2026-09-17 只读读取，站点已匿名化）：`generalCardPreset` 为「基础」，`generalCardKeys` 已包含 `remainingValue`，`show_price` 开启，「未登录时隐藏价格」关闭。应用候选后，首页会出现「剩余价值」卡；需要汇率时浏览器向 `open.er-api.com` 发起请求，其后当天复用缓存。

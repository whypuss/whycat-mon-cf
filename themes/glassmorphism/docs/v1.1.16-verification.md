# v1.1.16 发布前验证记录

## 范围

本版本修复 CFSM 开启全局 Turnstile 后主题无法加载数据的问题（#3），包含以下提交：

| 提交 | 内容 |
|---|---|
| `5031a7e` | 按 CFSM 默认前端流程渲染 Cloudflare 官方验证组件，取得令牌后经 `/api/config` 换取凭据。同时发送 `X-Turnstile-Verified` 与 `X-Turnstile-Token`。403 时通知订阅方重新验证，站点配置不带验证头重取。验证后首页、详情页与节点选择器列表重新拉取 |
| `a72d446` | 验证期间加载遮罩隐藏加载动画与 Loading 文字 |
| `e118b44` | 验证内容放入 AppDialog 同款面板，并预留组件 300×65 的位置。浏览中途重新验证时遮罩改用 AppDialog 的遮罩。组件配色跟随主题解析出的明暗 |
| `eadd076` | 组件关闭或重试前调用 `turnstile.remove()`，与 CFSM 管理端一致 |
| `5f8dd90` | 首页验证后走手动刷新的同一路径，REST 之后执行 `realtime.sync()`，恢复实时更新 |

其余提交只改版本号、发布说明、README 与文档。构建产物不嵌入版本号，所以版本号变更不影响产物。未开启 Turnstile 的站点，加载遮罩的两个新属性均为关闭，行为与 v1.1.15 相同。

## 本地无头浏览器验证

用本机 Chrome 的无头模式通过 CDP 驱动本地 mock。mock 按 CFSM 网关规则模拟全局 Turnstile：`/api/ws` 与不带验证头的 `/api/config` 放行，其余接口缺少凭据时返回 403。验证组件加载真实的 Cloudflare 脚本，并使用 Cloudflare 公布的测试 site key，分两种：
- 始终通过的 key，用于流程；
- 强制交互的 key，用于稳定截图，未做任何点击。

每个场景使用独立的浏览器上下文，避免凭据在场景间串用。

### 验证流程

| 场景 | 结果 |
|---|---|
| 首页冷启动 | 验证后节点正常加载 |
| 凭据有效期内刷新 | 不再要求验证 |
| 首页浏览中途凭据失效 | 刷新时弹出验证，通过后数据恢复 |
| 详情页冷启动 | 详情与节点选择器均正常 |
| 详情页浏览中途凭据失效 | 顶栏刷新触发验证，通过后数据恢复 |
| 设置页冷启动 | 表单正常显示 |
| 设置页保存时凭据失效 | 保存返回 403 后弹出验证。草稿在验证期间保留，再次保存成功，后端值与草稿一致 |

- 首次打开与中途过期两种情况通过验证后，控制台都没有 Cloudflare 的 `Cannot find Widget` 警告。
- 实时更新：
  - 首页验证后建立 `subscribe=all` 的 WebSocket，状态为 Live updates，与未开启 Turnstile 时一致；修复前首页验证后不建立连接。
  - 详情页验证后订阅对应节点。
  - 各场景均无 `WebSocket is closed before the connection is established` 警告。

### 布局与样式

测量计算样式与几何，并截图人工复核：
- 验证期间没有加载动画与 Loading 文字。
- 面板 326×125，验证组件容器在组件出现前后都是 300×65，不跳动；在 1280 / 390 / 360 宽度下水平居中，无横向溢出。
- 冷启动沿用原加载遮罩；浏览中途重新验证时遮罩为 `rgba(0, 0, 0, 0.45)` 与 `blur(2px)`，与 `.app-dialog__overlay` 相同。截图像素比对显示，背景处亮度为原来的 0.55。
- 站点强制深色而系统为浅色时，面板与验证组件均为深色。

### 全站回归

29 个场景分别在未开启 Turnstile 与开启 Turnstile 两种条件下运行，与 v1.1.15 的结果一致：
- 25 个场景正常加载；
- 配置 500、节点列表 500、历史 500、节点 404 四个场景显示既有的错误提示。

开启 Turnstile 且配置返回 500 时拿不到 site key，无法显示验证，页面如实显示错误。

## 线上复验

生产站点开启了全局 Turnstile。依次以 `preview-main` 的完整提交 SHA 地址安装各次预览，最后一次为 `c3ec9a7`（来源 `5f8dd90`）。每次安装后，线上入口文件与 24 个资源都和对应预览逐字节一致。

- **只观察渲染的检查**：用无头浏览器检查首页、设置页与详情页，覆盖 1280 / 390 / 360 宽度和浅色 / 深色，从不点击或通过真实验证。
  - 验证组件显示在面板中，没有加载动画，无横向溢出。
  - 验证前页面不呈现任何节点数据。
  - 请求顺序为 `/api/servers` 403、`/api/config` 200、Cloudflare 脚本 200；详情页的 `/api/server` 同样为 403。
  - 页面控制台没有错误、警告或异常。
- **真实浏览器人工确认**：通过验证之后的流程由站点维护者在真实浏览器中确认。
  - 首次打开验证后数据正常加载。
  - 凭据失效后重新打开页面，验证后数据恢复。
  - 浏览中途凭据失效后点击顶栏刷新，弹出验证窗口，通过后数据恢复。
  - 控制台不再出现 `Cannot find Widget`。
  - 首页验证后显示 Live updates，卡片数值实时变化。

控制台中剩余的输出都不是主题产生的：
- 被拒绝请求的 403 记录；
- Cloudflare 验证组件页面自身的提示，如 `powerPreference`、`OTS parsing error`；
- Cloudflare 框架页面响应头的 `Permissions-Policy` 提示；
- 浏览器扩展拦截 Cloudflare 在边缘注入的 Web Analytics 脚本时的 `ERR_BLOCKED_BY_CLIENT`。

# 厂商 / ASN 标签约定

本文档说明主题如何在 CFSM 上复刻 Komari 详情页的「厂商」，可以直接转给 CF-Server-Monitor 作者参考。

## 结论

- **CFSM 服务端不需要任何改动。** 作者的意见是不为厂商单独加数据库列，由运营者写进 tags。主题已按这个方案实现。
- 运营者在后台节点的「标签」里按下面的格式填写 ASN 和组织名，主题会识别出来，显示在详情页顶栏的厂商标识，以及系统信息卡的「厂商」格里。
- 识别出的这两类标签不再显示为普通标签。
- 主题只解析运营者自己填写的文本：不查询 IP，不访问任何外部 ASN / Geo 服务，也不猜测任何值。

## 标签格式

CFSM 保存标签时（`src/handlers/admin.js`），先按英文逗号拆分，再用 `[^\p{L}\p{N} ._\-]` 清洗每一项：
**冒号会被删掉**；单个标签最长 32 个字符，最多 12 个标签。约定格式必须能在这一步清洗之后保留下来：

| 用途 | 当前 CFSM 可以直接保存的写法 | 说明 |
|---|---|---|
| ASN | `AS3258`，或 `asn AS3258` / `asn-AS3258` / `asn_3258` | 裸写的 `AS` 号至少要 3 位数字，避免把 `AS1` 这类可用区简写误认成 ASN |
| 组织 / 厂商名 | `org xTom Japan Corporation` / `org-xTom` / `org_xTom` | 前缀和名字之间必须有空格、`-` 或 `_` |

几个需要注意的地方：

- `asn:AS3258` 保存后会变成 `asnAS3258`，主题仍然能识别。
- `org:xTom` 保存后会变成 `orgxTom`，这和 `organic` 这类普通标签无法区分，主题**不会**识别。组织名请用空格或连字符分隔。
- 组织名里不能有英文逗号，否则会被拆成两个标签。
- 前缀占用 32 字符上限中的几个字符，过长的组织名会被 CFSM 截断，主题显示的是截断后的原文。
- 同一类标签写了多个时，取第一个。

## 显示规则（与 Komari 一致）

识别逻辑逐段移植自 Komari `utils/providerInfo.ts`，包括关键词库、ASN 库、文本归一化和合并规则：

1. **商家**：从节点名称、分组、地区和普通标签里匹配厂商关键词；匹配到词典项时显示对应厂商。主题设置里的「厂商别名」（`providerAliases`，格式 `厂商:别名1,别名2;厂商2:别名`）优先。
2. **网络**：ASN 命中上游 ASN 库时取库里的名字；否则用组织名匹配关键词库；再不行就显示组织名原文。
3. 商家和网络不同时并列显示为 `商家 / 网络`，相同时只显示一个。
4. 「厂商」格显示 `厂商 · ASN`（上游是 `城市 · 厂商 · ASN`，CFSM 没有城市信息）。什么都识别不到时与上游一样显示 `-`。
5. 顶栏厂商标识的 tooltip 逐行对应上游的「商家 / 来源 / 网络 / ASN / Org」，另外多一行「ASN / Org 取自节点标签，未做 IP 查询」，注明数据来源。

## 给作者的可选建议（不是必须）

1. **把冒号加入标签清洗白名单**：只需把正则改成 `[^\p{L}\p{N} ._:\-]`。这样 `asn:AS3258`、`org:xTom` 这种更直观的写法可以原样保存，主题两种写法都识别。
2. **CFSM 自带前端区分显示**：带 `asn` / `org` 前缀的标签属于厂商信息，CFSM 自己的首页和后台如果不做处理，会把它们当普通标签显示出来。可以隐藏，也可以单独展示。
3. **以后如果要自动识别**：可以在服务端根据 Agent 上报的 IP 查询 ASN 和组织，写回标签或独立字段。公开接口只输出组织名和 ASN，不输出 IP。

## 关于 GPT 补充建议的评估

- **同意**：使用固定前缀（`asn` / `org`），并且和用户自定义标签区分开。这两个前缀正好对应 Komari 厂商解析函数的 `asn` 和 `org` 两个输入，主题可以直接复用上游逻辑。
- **需要修正的一点**：建议里的 `asn:AS3258`、`org:xxx` 在当前 CFSM 存不进去，冒号会被删掉。在作者放开冒号之前，请按上表用空格或连字符。
- **说法不准确的一点**：这些标签不是「系统生成」的。按作者的回复，它们是运营者手动填写的。区分显示已经在主题这边完成，不依赖 CFSM 改代码；CFSM 自带前端是否区分，由作者决定（见上一节第 2 条）。

# v1.1.13 候选第六轮 Q／R／S 审计

> 本文件是候选审计记录，不是发布说明。基线为 `main` 的 `5443900`；`package.json` 保持 `1.1.12`。最终提交、CI 与 `preview-main` SHA 以交付回复为准。以下站点名与节点均为本地 mock 的虚构样本，不含用户线上数据。

## 修改边界

- Q：启动时只读取一次 HTML `<title>` 与同源 API Base，生成展示用的可信标题快照；详情页继续校验节点所属来源。`AppHeader` 首次 setup 即解析 favicon，失败时保留首字和圆点回退。实测 data URI 配 `decoding="async"` 曾有约 46ms 的 `naturalWidth=0`，改为同步解码后首个 DOM 观测即为完整图标。
- R：`App.vue` 在唯一的背景层后挂载一次 `LoadingCover`，首页、详情和设置在冷启动遮罩期间保留顶栏但不渲染主体／Footer。配置与入口首批数据确定后一次性关闭，失败也关闭；之后切页和手动刷新继续走既有骨架／错误态。多源详情若所属后端配置仍在等待，沿用原详情门禁，避免遮罩刚退就露出骨架。
- S：`App.vue` setup 发起配置，首页和详情入口同时发起列表；设置入口不发列表。页面首次挂载复用在途 Promise，若预取已完成则不重复发起；后续刷新行为不变。没有修改任何 wire 适配、WebSocket、History 或背景状态机。

## 本地浏览器时间线

本地生产构建由忽略的 `work/visual-server.mjs` 服务。HTML 临时模拟 CFSM 注入 `<title>首屏测试站</title>` 与 data URI favicon，设置 `configDelay=1500`、1 个虚构节点。测试探针在 HTML 里仅记录 DOM、`fetch` 和资源时间；数字为单次运行的 `performance.now()` 毫秒，受本机缓存和调度影响。上游对照来自只读 Komari 源码的已有构建，使用同一浏览器与本地 mock。临时探针和延迟参数不进入提交。

| 入口 | 首次遮罩／主体 | 请求开始→结束 | 主体出现／淡出开始 | 遮罩移除 |
|---|---:|---|---:|---:|
| 首页 `#/` | 191ms／无 | config 100→1619；servers 109→156 | 1643ms | 1973ms |
| 详情 `#/server/visual-node-01` | 177ms／无 | config 73→1587；servers 73→95；server 174→2700（人为延迟） | 2768ms | 3130ms |
| 设置 `#/settings` | 82ms／无 | config 49→1561；**无 servers** | 1578ms | 2003ms |

首页配置已返回但列表仍等待、以及详情列表已返回但单节点仍等待时，遮罩保持。所有首帧顶栏都是“首屏测试站”加完整图标，无骨架条／几何圆点；配置成功后标题未再变化。无可信 HTML 标题时，冷启动期间仍是骨架条。`elementFromPoint` 在页面中心和顶栏坐标均命中 `.loading-cover`；它与上游一样为 `z-index:20`，由 `#app` 的层叠上下文盖住内部顶栏，不改变挂在 `body` 上的弹层层级。

冷启动后从首页点进详情，路由时间线没有任何 `cover:true` 记录，只有原详情骨架；详情页手动按“刷新 REST 数据”时，主体保留且遮罩仍不存在。配置 503、列表 503、详情 503 三种 mock 失败都退出遮罩，分别显示既有“站点配置读取失败”“无法加载节点”“服务暂不可用”状态。关闭页面动画时 `data-motion=reduced`，遮罩从存在直接变为移除，没有 `loading-cover-leave-*` 类。

## 与 Komari 的浏览器计算样式对照

以下均读取 `getComputedStyle`，非只看源码。浏览器对上游 Tailwind 的 `oklch` 和本主题构建后 CSS 的等价 `rgb` 使用了不同的序列化；颜色在源码中仍是上游原令牌。自定义背景并非替换整个 `background`：与上游一样只覆盖 `background-color`，保留原来的径向／线性渐变。

| 项目 | Komari | CFSM | 结果 |
|---|---|---|---|
| 浅色普通背景 | 16% 中心白色径向渐变 + slate `0.34→0.42` 线性渐变 | 相同 | 对齐 |
| 深色普通背景 | 20% 中心 slate `0.12` 径向渐变 + `rgb(15 23 42 / 0.72)` | 相同 | 对齐 |
| 浅色自定义背景 | 保留浅色渐变，`background-color: rgba(15,23,42,0.1)` | 相同 | 对齐 |
| 深色自定义背景 | 保留深色径向渐变，`background-color: rgba(15,23,42,0.08)` | 相同 | 对齐 |
| 普通／自定义转圈 | 28／20px，2px 边框，1s 线性旋转 | 相同 | 对齐 |
| 普通文字 | `Loading...`，14px／20px；浅色 `oklch(0.34 0.02 285.938)`、深色 `oklch(0.86 0.012 286.067)` | 相同；浏览器序列化为 `rgb(55,55,66)`／`rgb(208,208,217)` | 对齐 |
| 指示器前景 | 浅色 `oklch(0.11 0.01 285.823)`、深色 `oklch(0.985 0 0)`；自定义白色 75% | 相同；浏览器序列化为 `rgb(4,4,7)`／`rgb(250,250,250)`／`rgba(255,255,255,0.75)` | 对齐 |
| 指示器过渡 | opacity 240ms；transform 280ms cubic-bezier(0.22,1,0.36,1) | 相同 | 对齐 |
| 遮罩淡入／淡出 | 200ms ease-out／300ms ease-in | 相同；关闭页面动画时禁用 | 对齐 |

自定义背景暂存值为“启用”时，首次可见遮罩即是 20px、无文字、浅色 `0.1` 的变体；在 1500ms 配置返回后仍保持同一变体，没有中途跳换。已确认的设置若禁用自定义背景，则按实际设置返回普通变体。

## S 项同环境对照

用 `git` 的干净 `5443900` 基线构建独立本地副本，使用相同 mock、虚构 HTML、`configDelay=1500`、1 个节点、同一浏览器测量。旧版没有 LoadingCover，因此只能比较请求时序与“首批真实主体可见”时点，**不能虚构旧版遮罩结束时间**。

| 观测 | 旧基线 | 新实现 | 差值 |
|---|---:|---:|---:|
| `HomeView` 资源完成 | 87ms | 142ms | 本次新资源晚 55ms |
| `/api/config` 发出 | 144ms | 116ms | 提前 28ms |
| `/api/servers` 发出 | 145ms | 117ms | 提前 28ms |
| 发请求相对路由资源完成 | 晚 57／58ms | 早 26／25ms | 顺序已反转 |
| 首批真实首页主体出现 | 1694ms | 1655ms（开始淡出） | 提前 39ms |

新实现 300ms 的上游同款淡出会让遮罩最终移除晚于主体就绪，这是新增的视觉过渡，不是请求变慢。一次冷启动的首页与详情均只有各 1 个 `/api/config`、`/api/servers` 请求；详情另有 1 个 `/api/server`，设置只有 1 个 `/api/config`。`tests/bootstrap-store-sharing.test.ts` 还在延迟的 store Promise 上证明页面消费者复用同一在途请求。

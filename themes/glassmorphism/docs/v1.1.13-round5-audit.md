## 改动与测试

- `App.vue` 在 `<RouterView />` 前挂载唯一的 `DynamicBackground`；`HomeView.vue`、`ServerDetailView.vue`、`ThemeSettingsView.vue` 删除各自的导入与挂载，不改各页内容结构。
- `#app` 增加 `position:relative; isolation:isolate`，让路由外的背景 `z-index:-1` 仍位于页面内容后、`html` 底色前。不改背景状态机、图层、过渡、遮罩、模糊或冷启动规则。
- 新增 `tests/background-single-mount.test.ts` 的 `mounts one DynamicBackground outside RouterView and none in the three pages`。测试先于修复运行，在旧版 `App.vue` 找不到背景挂载时失败；修复后通过。没有修改或放宽已有断言。
- 原 `tests/background-media-state.test.ts` 中 `preloads the other URL on a light/dark switch and restores default while waiting` 继续约束明暗切换重新预加载；其它第四轮图层与失败回退测试未改。

## localhost 切页实测

本地生产构建由被忽略的 `work/visual-server.mjs` 服务。自定义站点通过 mock 的 `POST /api/theme_options` 写入图片背景，图片使用本地构建资产，不涉及线上真实数据。只在被忽略的 mock 脚本临时注入测试标记：记录首个背景 DOM 引用、替换次数和 `Image` 构造次数，并记录自定义图片的服务端请求；测试后已移除注入、停止两个 mock。浏览器使用可见的本地页面；每次读到的媒体计算 `opacity` 均为 `1`。

| 站点 | 路径 | 与首页初始背景同一 DOM 节点 | `Image` 构造累计 | 默认层 | 媒体层 / 淡入 |
|---|---|---|---:|---|---|
| 自定义图片 | 首页（稳定后） | 是，替换 0 次 | 1 | 无 | 图片在，opacity 1 |
| 自定义图片 | 详情 | 是，替换 0 次 | 1 | 无 | 图片保持，opacity 1 |
| 自定义图片 | 设置 | 是，替换 0 次 | 1 | 无 | 图片保持，opacity 1 |
| 自定义图片 | 返回首页 | 是，替换 0 次 | 1 | 无 | 图片保持，opacity 1 |
| 默认背景 | 首页 | 是，替换 0 次 | 0 | 在，opacity 1 | 无媒体 |
| 默认背景 | 详情 | 是，替换 0 次 | 0 | 在，opacity 1 | 无媒体 |
| 默认背景 | 设置 | 是，替换 0 次 | 0 | 在，opacity 1 | 无媒体 |
| 默认背景 | 返回首页 | 是，替换 0 次 | 0 | 在，opacity 1 | 无媒体 |

自定义站点在完整切页路径中，服务端仅收到 **1 次**自定义图片请求；导航没有再次构造预加载器，也没有重新露出默认层或触发淡入。为确认原有明暗行为，自定义站点另设不同的暗色图片：点击顶栏明暗按钮后 `Image` 构造数从 1 到 2，待暗色图加载时默认层短暂出现，完成后只剩暗色媒体且 opacity 为 1。这是配置地址变化时的既定行为，不是切页回归。

## 三页根容器遮挡检查

首页 `.app-root`、详情 `.app-root.detail-root`、设置 `.app-root.settings-root` 的计算 `background-color` 均为 `rgba(0, 0, 0, 0)`，`isolation:isolate`；应用根 `#app` 为 `isolation:isolate`，背景为 `z-index:-1`。本地截图中自定义图与默认图都显示在面板背后，页面根容器没有不透明遮挡。未发现新增的 `/api` 请求。

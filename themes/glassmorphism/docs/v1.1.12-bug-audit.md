# v1.1.12 Bug 审计

## 范围与基线

- 审计基线：`b21ad489eb3555bf4204cd5bc7c83b041462c667`（v1.1.11 之后的干净 `main`）。
- 本轮只处理可复现的稳定性、状态、数据真实性与请求生命周期问题；没有新增产品功能，没有更改既有页面结构，也没有改变 Agent `wss_report_interval`。
- REST、WebSocket、History、probe 三态、多 API Base、JWT / Turnstile 与 `theme_options` wire 契约保持不变。
- 先以源码 `main` 加可安装滚动预览 `preview-main` 完成候选验证；线上只读复核通过后，再创建 v1.1.12 Tag、Release、不可变 `theme-v1.1.12` 产物标签并推进稳定版 `theme-dist`。
- 浏览器回归以仓库忽略的确定性本地 mock 为主，并在正式发布前对已应用预览的线上环境做匿名只读冒烟复核；本文不包含真实站点地址、节点名称、价格或运行数据。

## 站点标题专项 A～I

| 场景 | 结果 |
|---|---|
| A. 首页直接冷启动 | 延迟配置期间 Header 显示固定尺寸 skeleton，品牌使用 favicon 或几何占位；不出现 `CF Server Monitor`；返回后直接显示真实标题。 |
| B. 首页强制刷新 | `document.title` pending 阶段保留中性的包标题，不写假站点名；配置完成后写真实站点名。 |
| C. 已有配置重新渲染 | 直接复用真实 app config，不制造第二次 pending 或配置请求。 |
| D. 配置请求失败 | 节点列表独立完成；请求期间仍为 pending；503 明确结束后才采用既有 `CF Server Monitor` fallback。 |
| E. 首页 → 详情 | 单源直接复用已加载配置，Header 与 `document.title` 不闪默认值。 |
| F. 详情直接刷新 | `/api/server`、列表、历史与配置并发；节点先返回时 `document.title` 仅写节点名，Header 保持占位；配置返回后组合真实站点名。 |
| G. 多数据源 | A/B 使用不同标题；打开 B 时观测到 `节点名` → `节点名 · B`，Header 为占位 → B；从未出现 A 或默认站点名。 |
| H. favicon / brandInitial | favicon 成功时 pending 与 ready 都保持 32×32 图片；favicon 失败且 pending 时显示固定几何标记，不闪 `C`；真实标题到达后才显示真实首字。 |
| I. `document.title` | 首页 pending 不写假站点名；详情 server 先到只写 server name；切 source 时清空上一 source 标题；最终才组合 owning source 标题。 |

## 数据链与竞态回归

- REST：五个既有端点未变；401、403、404、409、500、503 继续按原分类呈现。配置、列表和 History 的 last-good 快照不会被旧请求或失败请求错误清空。
- WebSocket：首页仍使用 `subscribe=all`，详情仍只订阅当前 server ID；每个 `samples[]` 顺序处理，partial merge 保留 `false / null / 0 / number`。强制关闭一次连接时，首页与详情都短暂进入 REST 补偿提示，退避恢复后提示消失且指标继续变化。
- History：1 小时共享请求仍只发一次；实时→30 分钟→实时后网络速率从 `430 KB/s / 1.2 MB/s` 继续变化到后续真实 mock 样本，没有停住或补假点。401 / 409 / 503 与空历史均保持详情主流程可用。
- Probe：旧四线路和 Node 1～4 的三态契约未改变；配置 pending 时先等待 owning labels，不再闪默认线路名。
- 设置：快速双保存归并为一次 POST 和一次 `/api/config` 回读；失败仍保留 draft。

## 性能与包结构

- 没有新增运行时依赖，也没有改 `bun.lock`。
- 详情冷启动移除配置→节点的请求瀑布；同一配置、列表和保存请求均复用 in-flight。
- 构建产物仍只允许根级 `index.html` 与 `assets/`；当前预算内实测为约 3069.7 KiB JS、106.5 KiB CSS、6123.3 KiB 总资源。
- `preview-main` 只接受 `verify` job 产出的已验证 ZIP，也不修改源码工作树；正式版本仍只由 `v*` 标签触发独立发布链路。当时的发布脚本使用普通 fast-forward；v1.1.13 发布后的维护将其改为无父单提交，并用 `--force-with-lease` 防止并发覆盖，不创建 tag / Release。

## 剩余已知限制

1. 全新浏览器且没有本地主题覆盖时，服务端 `theme_options` 在 `/api/config` 返回前不可知；页面先使用内置安全主题，响应后才采用站点主题。缓存旧后端主题会在多源或站点改配置后制造更严重的错误，本轮没有采用这种伪修复。
2. GitHub Issue #1 继续记录上游限制；主题端不采用降低安全边界的绕过方案。
3. `preview-main` 是后续 `main` 的滚动预览，不提供稳定内容保证；v1.1.12 应固定安装 `theme-v1.1.12`，或使用跟随最新稳定版的 `theme-dist`。

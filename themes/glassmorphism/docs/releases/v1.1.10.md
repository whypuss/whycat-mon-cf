本版本修正首页实时总上行 / 总下行在同一个上报轮次内连续显示多个中间值的问题，并修复详情页进入「实时」后偶尔长期停在等待提示、不再更新的问题。Agent 端配置的 `wss_report_interval` 完全保留，前端不会把它改成 10 秒或任何其它固定上报间隔。

## 更新内容

### 首页实时合计按上报轮次整体刷新

多节点场景中，同一轮的 WebSocket 消息可能错峰抵达。旧实现每收到一台节点就立即更新 store，因此总上行 / 总下行会在一次上报轮次中连续重算多次，访客会先后看到几个不同的中间合计。

本版本改为：

- 按当前最快的 Agent `wss_report_interval` 推导一个短收集窗口，只合并同一轮错峰抵达的节点消息；
- 同一轮所有 apiBase 的样本一次性写入 store，首页总上行 / 总下行只重算一次；
- 每条 `batchUpdate.samples[]` 仍按原顺序执行 partial merge，不丢弃、不平均、不插值；
- 收集窗口短于下一轮上报，Agent 配置的 1～5 秒真实节奏不变；页面隐藏、暂停、超时或订阅集合变化时会丢弃尚未完成的一轮，避免旧样本在恢复后写回。

### 详情页实时连接与历史垫底

协议复核发现，`/api/ws?subscribe=<serverId>` 建连后如果只等待 `hello`、没有再发送订阅帧，CFSM 不会触发 Agent 的实时上报提示；在没有其它活跃订阅者时，这条详情连接可能一直收不到 `batchUpdate`。因此页面会停在“正在采集实时数据”，即使 Agent 正在按配置上报。

本版本与 CFSM 官方前端保持一致：

- 单节点连接 open 后发送 `{ type: "subscribe", scope: <serverId>, ids: [] }`，激活该节点的实时上报；
- 仍然只订阅当前节点，不使用 `subscribe=all`，不拉取或过滤其它节点；
- 进入「实时」时优先复用页面已经加载的真实 History，立即取最近 10 分钟垫底；只有当前历史确实没有近点时才补取 10 分钟 History；
- 刷新、切换节点或切换固定时间范围再返回实时后，缓冲都会重新取得真实垫底并继续逐条接收 WSS 样本；
- 详情页仍完整保留 Agent 的 1～5 秒样本，实时图不降采样，超过 1 分钟没有真实样本才画断点。

## 安装

在 CFSM 后台「主题商店 → 自定义主题 URL」中填入不可变标签：

```text
https://github.com/allury/CFSM-Glassmorphism/tree/theme-v1.1.10
```

也可以下载本页的 `CFSM-Glassmorphism-v1.1.10.zip` 手动安装：解包后，将根目录的 `index.html` 与 `assets/` 部署到主题目录。

回退到上一版：

```text
https://github.com/allury/CFSM-Glassmorphism/tree/theme-v1.1.9
```

<summary><b>已知限制</b>（本版本未解决，如实列出）</summary>

- **首页合计是各节点最新快照之和**：节点由不同 Agent 独立上报，服务端不保证它们拥有完全相同的采样时间；本版本消除的是同一轮的连续中间渲染，不伪造一个服务端不存在的全局同步时间点。
- **实时负载缓冲只存在当前页面内存中**：刷新或离开详情页后不会保留上一段浏览器缓冲；重新进入会用真实历史重新垫底。
- **实时断点使用 1 分钟绝对阈值**：短于 1 分钟的网络停顿不会画成断线；原始样本没有被补齐或改写。
- **首页每次手动刷新会发两个请求**：站点配置与节点列表各一次。
- **多后端部署缺少生产环境验证**：多 apiBase 的原子提交与来源归属由自动化测试覆盖。
- **移动端触屏未实测**：提示气泡与图表说明在真实触屏设备上的唤出方式没有实机证据。

</details>

<details>
<summary><b>验证与技术细节</b></summary>

**匿名化协议证据**：多节点订阅可观察到同轮消息错峰抵达。单节点 URL 只等待 `hello` 时可能收不到 `batchUpdate`，发送同 ID 的订阅帧后会收到 `subscribed` 与后续样本。History 同时可返回真实点，因此详情空白不是 Agent 配置被改成固定间隔，而是订阅激活与垫底时序问题。

**首页收集窗口**：取当前最快上报周期的一半，并限制在 250～1000ms；1 秒上报使用 500ms，2～5 秒上报最多等待 1000ms。窗口只决定前端何时一次性提交同轮样本，不改变后端发送时间和任何样本值。

**数据真实性**：首页批次仍按 owning base 合并；缺失字段保留旧值，明确出现的 `false / null / 0 / number` 照常覆盖。详情仍使用 `/api/server`、`/api/history/all` 与 `/api/ws?subscribe=<serverId>`，不新增私有端点。

**质量门**：冻结依赖安装、代码检查、Bun 与 Node 两套类型检查、单元测试（551 项）、构建、产物校验与 diff 检查均已通过。新增回归覆盖多节点错峰消息只触发一次聚合、多 apiBase 原子写入、隐藏页面丢弃未完成批次、上报周期推导、单节点订阅帧、现有历史即时垫底，以及切换节点后实时模式重新垫底。

</details>

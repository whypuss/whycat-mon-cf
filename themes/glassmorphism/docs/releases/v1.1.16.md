本版本修复 CFSM 开启全局 Turnstile 后主题无法加载数据的问题（#3）。未开启 Turnstile 的站点不受影响，页面结构、交互、数据接口和 Agent 上报节奏均不变。

## 修复

- CFSM 开启全局 Turnstile 后，访客还没有验证凭据时，主题此前不会显示人机验证，节点列表、详情与历史数据的请求全部被拒绝（HTTP 403），页面无法加载数据。现在按 CFSM 默认前端的流程，在加载遮罩中显示 Cloudflare 官方验证组件。验证通过后取得 CFSM 凭据并继续加载数据，整页不刷新。
- CFSM 签发的验证凭据约 1 小时后失效。此后浏览中途的请求被拒绝时，页面会重新显示验证。通过后当前页面自动恢复数据，首页的实时更新同时恢复，设置页未保存的修改不会丢失。
- 数据请求同时携带 CFSM 的两种验证请求头 `X-Turnstile-Verified` 与 `X-Turnstile-Token`，与 CFSM 默认前端一致。本地凭据失效时，站点配置改为不带验证头重新读取。

## 变更

- 验证期间，加载遮罩只显示验证提示与验证组件，不显示加载动画。
- 验证内容放在与主题弹窗同样式的面板中。浏览中途需要重新验证时，遮罩改用主题弹窗的半透明遮罩，背后的页面不再与提示文字重叠。
- 验证组件的明暗配色跟随主题当前的明暗模式，不再跟随系统设置。
- 验证组件在关闭或重试前会先按 Cloudflare 的要求移除，浏览器控制台不再出现 `Cannot find Widget` 警告。

## 已知问题

- 开启 Turnstile 时，浏览器控制台会记录被拒绝请求的 403，以及 Cloudflare 验证组件自身输出的提示（例如 `Permissions-Policy`、`powerPreference`）。这些属于验证流程的正常输出，不影响使用。

## 安装

在 CFSM 后台「主题商店 → 自定义主题 URL」中使用稳定版构建产物标签：

```text
https://github.com/allury/CFSM-Glassmorphism/tree/theme-v1.1.16
```

也可下载本页的 `CFSM-Glassmorphism-v1.1.16.zip` 手动安装，压缩包根目录仅有 `index.html` 与 `assets/`。回退到上一版可使用：

```text
https://github.com/allury/CFSM-Glassmorphism/tree/theme-v1.1.15
```
